**Model, fixed throughout:**
- one local rule shared by every cell: Moore radius 1, constant 0 boundary, fixed steps per frame S;
- initial state: visible = the first frame, hidden = all 0;
- no frame injection, rule switching, time or coordinate inputs, or per-scene resets.

**Lossless only.** No approximate replay was run.

**Cost** = bytes of a file that decodes on its own.
- **Every file holds:**
  - the method id;
  - W, H, T;
  - the first frame (one shared coder);
  - the rule header (family, k, S, boundary, hidden init), or the recording or compressor payload.
- **Not counted, for every method alike:** the generic decoders (CA player, RLE / change-list decoders, zlib/bz2/lzma).

## 1. Did direct synthesis of small circuits work?
**Yes on the controls and the simple clips. No circuit was found on any Bad Apple clip, disc12 or bar12.**

- **Encoding:**
  - **circuit family:** G 2-input gates, each with an arbitrary function (4 truth-table bits) and inputs a < b from [tap inputs, earlier gates];
  - **outputs:** one selection per channel (visible, hidden);
  - **SAT constraints:** one-hot selection and mux clauses per circuit copy; the exact rollout of every observed frame is the hard constraint;
  - **symmetry handling:** every gate must be used, plus optional lex ordering of adjacent independent gates.
  - **SAT is monotone in G** (a buffer gate pads any smaller circuit), so UNSAT at G proves that no circuit with ≤ G gates exists in that structure.
- **Results:**
  - **Positive control pcA** (generated by a known 2-gate circuit, k=1, S=1): recovered at G=2; G ≤ 1 is UNSAT, so **2 gates is minimal (proved)**.
  - **Positive control pcB** (known 4-gate circuit, k=1, S=2): SAT at **G=3**, smaller than the generating circuit; G ≤ 2 is UNSAT, so 3 is minimal. The circuit differs from the original but replays the clip exactly.
  - **translate24** (moving block): G=0 is SAT. The output simply selects the west-neighbour tap, which is minimal.
  - **Every SAT circuit** was rolled out in Python as binary states, written to a file, and decoded from the file's bytes by Python and by the independent Node player (`player/decode_file.mjs`). All frames matched byte for byte.
- **Generalization from a prefix** (diagnostic only, not compression evidence):
  - circuits found on the first 3 frames of pcA, pcB and translate24 replay the full clips **and** the 18-frame extensions of pcA/pcB exactly;
  - disc12's 4-frame prefix has no circuit with ≤ 4 gates (UNSAT), so there was nothing to test.

**Gate-count bounds** (k1 = one hidden bit, k1s = neighbours' hidden readable, k2 = two hidden bits; S = updates per frame):

**Why the remaining runs failed: timeouts, not UNSAT.**
- Proof time grows about 30–50× per added gate. For example, ba32_3000_5 k1_S2 took 2 s at G=2, 25–30 s at G=3 and 605 s at G=4.
- At 1800 CPU-s, the search found no circuit at G=8 or G=12 either.
- **Every UNKNOWN** is a CPU-cap timeout. None was a memout: the peak was 6.65 GB, under the 16 GB cap.
- **Encoding improvements tried** (before/after kept, all on the ledger):
  - **v3 (one circuit copy per LUT entry, tied to the exp03 rollout CNF)** was 2.2–16× **slower** on every instance it could decide (disc12 G3 27 vs 4.8 s, ba32_3000_5 G3 55 vs 25 s, bar12 G2 43 vs 19 s, pcB G3 16 vs 1 s).
  - **Lex symmetry breaking** made no difference at G ≤ 3. It decided disc12 G=4 UNSAT in 144 s against 234 s without it (one run, about 1.6×).
  - The bottleneck is the search itself (circuit structure jointly with unknown hidden and intermediate states), not encoding size.
- **One implementation error,** found and fixed during the pilot:
  - the truth-table literal signs were inverted in the SAT encoding, so decoded circuits were wrong;
  - the SAT/UNSAT statuses were unaffected, because the inversion is a bijection;
  - pcB's pilot circuit failed its own replay check, so the error was caught and that circuit is excluded (`excluded_implementation_errors`);
  - a regression test now covers it.

## 2. Did direct synthesis beat the LUT → reduction route?
**There is nothing to compare on the clips that have LUT-route results.**
- On Bad Apple, disc12 and bar12 direct synthesis found no circuit. Its proved lower bounds are far below the gate counts of the LUT-route circuits (≥125 gates), so a smaller direct circuit is not excluded; it was simply not found.
- On pcA, pcB and translate24 direct synthesis gave 27, 29 and 19-byte files, but the LUT route was not run on these clips. There is no comparison there either.
- **LUT-route baselines in the new container** (490 files, all decoded in Python and Node):
  - **Two equivalence checks:**
    - **full level:** every converted circuit is truth-table equivalent to its LUT on all inputs (245 rows);
    - **reach level:** clip-replay equivalent only.
  - **Smallest file is a LUT encoding, never a circuit,** on every clip. For example, on ba32_3000_5 the best LUT file is 129 bytes and the best circuit file is 322 bytes (125 gates).
  - So a lower gate count does not mean a smaller file. The circuit's wiring references cost far more than LUT exceptions.

## 4. Neighbour hidden bits and extra updates
- **Storage cost per structure:**
  - The circuit encoding grows only logarithmically with the input count n. For ba32_3000_5, a 12-gate file is 78 bytes at n=10 (k1), 79 at n=11 (k2) and 80 at n=18 (k1s).
  - The LUT encoding's index space grows as 2^n per channel: 1,024 entries at n=10, 262,144 at n=18. Each exception then costs about 2·log2(gap) bits.
  - So the "LUT explosion" belongs to the LUT representation, not to the circuit file.
- **What each mechanism resolves:**
  - **Updates per frame (S):** a radius-1 rule spreads information at most S cells per frame (light cone). S=1 is impossible for every Bad Apple clip in any family; bar12 needs S=4. More updates resolve **reach**.
  - **Hidden memory (k):** with S=1 and the private family, cells with the same observed history must agree, and memoryless rules cannot handle a repeated frame. disc12 needs k ≥ 1 (frames 1 and 5 repeat). Memory resolves **history ambiguity**.
  - **Neighbour hidden (k1s):** it does **not** extend the light cone, because the radius is still 1. It changes what neighbours can communicate: disc12 becomes LUT-feasible at S=1 (CHECKPOINT_02, X4).
- **Gate counts:** in this campaign neither neighbour hidden nor more updates lowered the provable gate count. Every structure on ba32_3000_5 is UNSAT up to G=2–4 and UNKNOWN beyond. Their effect on achievable file size is **not measured**, because no circuit was found.

## 5. What kind of failure
- **UNSAT (proved):** the bounds in §1, and the certificates (S=1 for Bad Apple, S<4 for bar12, memoryless disc12, k0_S2 for ba32_3000_5 from CHECKPOINT_02).
- **Timeout (UNKNOWN):** every remaining G. These are not evidence that a large circuit is needed.
- **Implementation error:** the truth-table sign error. It was caught by the replay check, fixed, and regression-tested; no reported result depends on it.
- **Resource limit:** CPU caps only. No memouts, and no GPU use.

## 8. Next investment, and why
1. **Close the ba32_3000_5 window** (G = 5–12, k1_S2). It is the only Bad Apple case where a CA file could beat the best baseline with a circuit small enough for exact synthesis.
   - The proof cost per gate (30–50×) rules out plain ladders.
   - Better candidates:
     - **cube-and-conquer over the gate topology** (enumerate wiring DAG shapes, SAT on functions and hidden states), or a different solver (e.g. kissat), on the same instance and budget;
     - **non-degenerate gate restrictions** with a proof that no minimal circuit needs degenerate gates;
     - **fixing the hidden-bit trajectory class** in advance.
2. **Not recommended:**
   - LUT-route variants: the best LUT-route file is 1.4–2.8× the best baseline on each clip, and circuits from LUTs are larger still.
   - Longer clips before the 5-frame window is resolved: break-even G grows with length, but so does search cost.
